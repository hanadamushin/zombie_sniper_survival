# R9 実在の日本地図: 全地方の作り直しと通しの点検

R1〜R8 の途中で、共通部分（`tools/real/region.ts` の変換）に修正が入りました（R1: 鉄道のトンネル・地下鉄の読み違い、R2: スキーリフト・ロープウェイを線路として描いていた、など）。区域ファイルは作った時点の共通部分で変換されているので、**先に終わった地方には古い誤りが残っています**。
あなたの仕事は、**最終の共通部分で全 8 地方の区域ファイルを作り直し、全国を通しで点検すること** です。新しい機能は作りません。

## 作業の前提（毎回最初に確認。発注者の許可済み）

- このセッションは GitHub リポジトリ `hanadamushin/zombie_sniper_survival` へ**プッシュできる状態**で作業する。作業ディレクトリにリポジトリが無い、または読み取り専用でしか複製できない場合は、**最初に**リポジトリを書き込み権限つき（push）でセッションに追加し、複製してから作業を始めること。**発注者はこの追加とプッシュを事前に許可している**（このプロンプト自体が発注者からの指示）
- 作業の最後に、指定のブランチへプッシュしたうえで、`git ls-remote` でリモートのブランチがローカルのコミットと一致することを確かめてから終える。プッシュできないまま終えない
- **このセッションはクラウド環境「zombie_sniper_survival」で動かす**（国土地理院・e-Stat・国土数値情報へ接続できるのはこの環境だけ）。最初に `curl -s -o /dev/null -w "%{http_code}" https://cyberjapandata.gsi.go.jp/xyz/dem/10/909/403.txt` が 200 になることを確かめ、ならなければ作業を始めずに、環境が違うことを発注者に伝えて終える

## 読むもの
- `CLAUDE.md`、`docs/PROGRESS.md`（R0〜R8 の節。特に各地方が「共通部分を直した」と書いた箇所）
- `docs/realmap_guide.md`（末尾の「各地方からの追記」まで）

## 作業
1. 各地方の担当が直した共通部分の一覧を PROGRESS.md から作る。それぞれの修正が、修正より前に作られた地方に何を残しているかを書き出す
2. **最初に `npm run data` を 1 回だけ回して、戦略地図（`grid.json`・`infection_*.bin`）を作り直す**。R1〜R8 は衝突を避けるためこれを回さず、`tools/real/grid.ts` の修正だけを入れている（R3: 政令指定都市の地名が最初の区の役所の位置に出ていた。横浜市が川崎駅のセルに出て、川崎市が消えていた）。作り直した後、戦略地図で横浜・川崎・さいたま・名古屋・大阪・神戸・福岡の地名が正しいセルにあることを確かめる。感染の事前計算の結果（90 日目の分布）が R0 の記録から大きく変わっていないことも確かめる
3. 8 地方すべてを `npm run data:region -- <地方>` で作り直す。キャッシュ（`tmp/realdata/`）はこのセッションには無いので取得からやり直しになる（全国で約 8 万件・数時間）。止まっても再開できるので、地方ごとに終わったらコミットしてプッシュする
4. 全国の自動点検（`tools/real/check.ts`）と射線の点検（`tools/real/sightlines.ts`）を全セルで回す。各地方が認めた例外（道路の端がかすめるだけ、など）以外の失敗が出たら、その地方の手直しのファイルで直す
5. 作り直しの前後で、区域ファイルの合計の大きさと、各地方の点検の結果（例外の数）を表にする。手直しのファイル（見張り台・自衛隊）が作り直し後も効いているか確かめる
6. `npm run e2e` を **全件** 通す（約 1 時間以上。一度に終わらなければ spec ごとに分けてよい）。落ちたものは原因を調べて直す。古い乱数の地図に固定されていた試験は、R0 が仙台に移したのと同じように実データのセルへ移す
7. 全国の性能: 各地方で最も建物の多い区域と、全国で最も重い区域（東京の都心・大阪の中心など）で 3 指標を計測し、表にする

## 特に確かめること（R1〜R4 で見つかった、先に作った地方に残る誤り）
- 鉄道のトンネル・地下鉄が地上の線路になっている（R1 で修正。四国が対象）
- スキーリフト・ロープウェイが線路になっている（R2 で修正。北海道・四国が対象）
- 土地利用が読まれず陸が一面の砂浜になっている（R3・R4 で修正。**東北 約 120 セル（福島・山形・宮城の南部）、関東 約 61 セル（栃木・群馬の北部）**。中部との境界の水面の食い違い 8 セルもこれが原因）
- 戦略地図の地名と都道府県の食い違い（R5: セル 20111 が「大阪府」なのに地名が兵庫県の「尼崎市」）。`grid.json` を作り直した後、**全セルで「地名の市区町村が属する都道府県」と「セルの都道府県」が一致するか** を機械的に確かめ、食い違いの一覧と直し方を PROGRESS.md に書く（境界のセルは人口の多い方の県になるので、地名もその県の市町村から選ぶのが正しい）
- 作り直したら、これらのセルの区域の画像で直っていることを確かめ、PROGRESS.md に前後を並べる

## 受け入れ基準
- 全 8 地方の区域ファイルが最終の共通部分で作られている（作り直しの前後で、R1・R2 の修正の対象だった箇所が直っていることを例で示す: 札幌の地下鉄が地上にない、蔵王・ニセコのリフトが線路でない、など）

- `npm run check`・`npm run build`・`npm run e2e`（全件）が通る
- 全国の区域ファイルの合計が 120MB 以下
