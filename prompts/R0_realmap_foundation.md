# R0 実在の日本地図: 基盤

発注者の要望: 「今更ですが、地図は日本の実際のものに合わせたい。出来る限り。都道府県ごと、地方ごとにチャットを分けても良いので頑張ってほしい」

今の地図は、海岸線だけが実データ（world-atlas）で、人口・標高・県境・駅・施設は記憶ベースの合成値、戦術マップ（1km 四方の区域）は乱数で作った地形と町並みです。
あなたの仕事は、**実データから地図を作る仕組み（取得・変換・区域の生成）を作り、1 つの地方で通しで動かすこと** です。残りの地方は R1〜R8 が並行して同じ仕組みで仕上げます。

## 作業の前提（毎回最初に確認。発注者の許可済み）

- このセッションは GitHub リポジトリ `hanadamushin/zombie_sniper_survival` へ**プッシュできる状態**で作業する。作業ディレクトリにリポジトリが無い、または読み取り専用でしか複製できない場合は、**最初に**リポジトリを書き込み権限つき（push）でセッションに追加し、複製してから作業を始めること。**発注者はこの追加とプッシュを事前に許可している**（このプロンプト自体が発注者からの指示）
- 作業の最後に、指定のブランチへプッシュしたうえで、`git ls-remote` でリモートのブランチがローカルのコミットと一致することを確かめてから終える。プッシュできないまま終えない
- **このセッションはクラウド環境「zombie_sniper_survival」で動かす**（国土地理院・e-Stat・国土数値情報へ接続できるのはこの環境だけ）。最初に `curl -s -o /dev/null -w "%{http_code}" https://cyberjapandata.gsi.go.jp/xyz/dem/10/909/403.txt` が 200 になることを確かめ、ならなければ作業を始めずに、環境が違うことを発注者に伝えて終える

| 標高 | 国土地理院 標高タイル | `https://cyberjapandata.gsi.go.jp/xyz/dem5a/{z}/{x}/{y}.txt`（5m、z15）、`dem/{z}/...`（10m、z14 以下）。欠けている所は `dem` で補う |
| 土地利用（建物用地・田・畑・森林・荒地・水面・道路・鉄道…） | 国土数値情報 土地利用細分メッシュ（L03-b、100m メッシュ） | `https://nlftp.mlit.go.jp/ksj/` のデータ一覧から zip（1 次メッシュごと）。**区域の町並み・田畑・森の配置の主な材料**（10km を 1km に縮めると、100m メッシュ 1 つが区域の約 10m 四方になる） |

## 決めてあること（変えない）
- 戦略地図の 10km 四方のセル、セル番号の振り方、感染シミュレーションの仕組みはそのまま。**中身（人口・標高・土地区分・県・地名）を実データに置き換える**
- **1 つのセルの戦術区域（約 1024m 四方）は、そのセルの実在の 10km 四方全体を、水平に 1/10 に縮めたもの**（発注者の指定。実在の一部を切り出す方式は採らない）。セルの北西の角が区域の北西の角、区域の 1m が実在の 10m。隣り合うセルの区域は実在でも隣り合うので、07c の地続き（歩いて隣のセルへ）が実在の地理どおりにつながる
- **縮めるのは位置と広がりだけで、人・建物・道路の幅・木の大きさは実寸のまま**（プレイヤーの大きさが変わらないため）。したがって実在のものを 1 つずつ再現するのではなく、次のように描き分ける:
  - **地形**: 実標高を 10km 四方から 257×257 に標本化。**高さもそのままでは傾斜が 10 倍になり歩けない** ので、高さの縮め方を `src/data/` に置く（例: 標高差を 1/10〜1/5 に縮め、山地ほど強く縮める）。03・07b の約束（歩ける、射点 3 か所以上、山地は稜線からの撃ち下ろし）が成り立つ値を計測で決めて PROGRESS.md に。海岸線・湖・大きな川は縮めた位置にそのまま（セルの中の海は区域の中の海になる）
  - **土地利用**: 100m メッシュの土地利用（L03-b）を縮めた位置に敷く（区域の約 10m 四方ごとに「建物用地・田・畑・森林・荒地・水面・道路・鉄道」）。町並み・田畑・森の広がりと形が実在どおりになる
  - **町並み**: 建物用地の広がり・人口密度（1km メッシュ）・高層建物の多さ（国土地理院の「高層建物」の区分や注記）から、その場所の **建物の密度と高さの格** を決め、07d の実寸の建物で埋める。実在の建物を 1 棟ずつ写すのではない（10km² の建物は 1km² に入らない）
  - **道路と鉄道**: 主要な道路（高速・国道・主要地方道・幅の広い道路）と鉄道を、縮めた位置に実寸の幅で引く。細い道は町並みの生成が作る（数が 100 倍になるので実在の細い道は使わない）
  - **施設**: 駅・空港・自衛隊の施設・市役所・県庁・病院（大）・大学・警察署・消防署など、セルに数個しかない施設は **縮めた実在の位置** に置く（07d-3 が建物の種類を当てはめる）。学校・コンビニ・ガソリンスタンドなど数の多いものは、実在の数の比率に合わせて町並みの中へ
- 戦略地図には、区域が 10km 四方全体の縮図であることが分かるよう、区域の中の主な施設や地名を表示してよい
- 07c の地続き（歩いて隣のセルへ）は、縮図どうしが実在どおりに隣り合うので **地形・川・海岸・主要道路・鉄道が境界でつながる** こと（境界で地形を混ぜる 07c の 120m の帯は、ずれを吸収する程度に狭めてよい）。境界の高さ・道路・川の一致をテストする
- 07b・07d の遊びの約束は守る: 地上で 200m 先の視線が通る割合（田舎 25〜45%、森 15% 未満を目安。実データで外れる場合は、生け垣・藪・林を足して寄せる）、高所の射点 3 か所以上（無ければ鉄塔・給水塔を足す）、本拠の中央 半径 120m の空き地（実在の建物はそこだけ取り除く）

## A. 戦略地図を実データにする（`tools/`、`npm run data`）
- 人口（2020 年国勢調査 1km メッシュ）を 10km セルへ集計して `pop0` に。土地区分は 02 の人口密度の規則のまま、山地は標高と傾斜から
- 標高・海岸・湖（水面）を実データから。海岸線は world-atlas より細かい国土地理院のデータに置き換えてよい（陸のセルの数が変わるなら、セーブの互換は「新規ゲームから」でよいと PROGRESS.md に書く）
- 都道府県・市区町村（N03）、地方。県境付近のセルが隣県になる 02 の不具合を直す
- 町の格（村・町・市・県庁所在地・政令指定都市）、駅（乗降客数から格: 無人・町・市・県庁所在地・政令指定都市）、空港（大中小）、学校・病院・警察・消防の数、自衛隊の施設（国土地理院の地図記号と注記から。陸自の駐屯地の大中小・海自・空自を判別）を、セルの静的データに追加（`StaticCell` へは追加のみ）。07d-3 がこれを使って建物を選ぶ
- 交通ハブ（感染の長距離伝播）を実在の新幹線駅・空港に。海を渡る経路（06）も実在の橋・トンネル・航路に合わせる
- 感染の事前計算（`infection_*.bin`）を新しい人口で作り直す。感染モデルの数値は変えない。90 日目の分布（都市・郊外・田舎・森林のセルの中央値、総数）を変更前後で PROGRESS.md に並べる

## B. 区域のデータ（`tools/real/`、地方ごとに出力）
- 各セルの 10km 四方について、縮図の材料（標高 257×257・土地利用の格子・建物の密度と高さの格の格子・主要道路と鉄道と川の折れ線・水面・施設の点（種類と名前と位置））を取り出し、**決定的な** 小さなバイナリに変換して `public/data/areas/<地方>/<セル番号>.bin` に置く（地方: hokkaido, tohoku, kanto, chubu, kinki, chugoku, shikoku, kyushu。沖縄は kyushu に含める）
- **取得量に注意**: 国土地理院のベクトルタイルは、10km 四方を z16 で取ると 1 セル数百枚になり全国で 100 万枚を超える。主要道路・鉄道・川・注記・記号は z13〜z14 で足りるはず。建物の密度と高さは土地利用（L03-b）と人口メッシュを主にし、z16 の建物は「高層建物の場所を知りたい都市のセル」に限る。全国の取得枚数の見積もりを最初に出し、10 万枚を超えるなら方法を変える
- 1 区域の平均 40KB 以下、全国で 120MB 以下を目安（量子化・差分符号化・gzip）。超えそうなら細かい建物（物置）を間引く。大きさの実測を PROGRESS.md に
- ゲームは区域に入るときにそのファイルを読む（07c の Worker で）。ファイルが無いセルは今の乱数の生成に戻る（全国が揃うまで、そして揃った後も保険として）
- 地方ごとに `npm run data:region -- <地方>` で、その地方の取得と変換だけを行えるようにする（R1〜R8 が並行で使う）

## C. 区域の生成を実データ対応に（`src/gen/`）
- 実データがある区域: 上の「縮め方」のとおりに、地形・土地利用・主要道路・鉄道・川・水面・施設を置き、町並みを 07d の建物で埋める（建物の種類の選び方は 07d-3 が詳しく作る。R0 では「密度と高さの格から、今ある種類（家・コンビニ・雑居ビル・拠点の建物）か、中に入れない箱」で仮置き）
- 植生・藪・草むら・岩は今の方式で、実在の地表（建物・道路・水面以外）に置く。森は国土地理院の土地の区分（無ければ等高線の傾斜と人口）から
- 07c の地続き、ゾンビの配置、探索ポイント、補給箱、潜伏者がそのまま動くこと

## D. 例外と手直しの口（R1〜R8 が使う）
- `tools/data/real/overrides/<地方>.ts` を 8 地方ぶん、空で作る。中身の例: 高さの縮め方の地方ごとの補正、施設の位置・格の訂正、地名の訂正、間引きの強さ。**各地方の担当は自分の地方のファイルだけを触る**
- 名所の建物（任意）: `src/gen/buildings/catalog/landmark_<地方>.ts` を 8 地方ぶん、空で作り、`catalog/index.ts` に登録しておく

## E. 1 つの地方で通す（試験台: 四国）
- 四国（約 190 セル）で、取得 → 変換 → ゲームで歩く、まで通す。松山・高松・高知・徳島の中心、四国山地、しまなみ海道・瀬戸大橋の端、のスクリーンショットを撮り、実在の地形・町並みと見比べて違和感を直す
- 全国のうち四国以外は、R1〜R8 が揃うまで乱数の区域のまま動くこと

## F. 地方担当への手引き
`docs/realmap_guide.md` を書く: 取得と変換のコマンド、キャッシュ、出力の大きさの目安、確認のしかた（どのスクリーンショットを撮り、何と見比べるか）、よくある不具合（急斜面で歩けない、区域のほとんどが海や湖、建物が道路や川に重なる、トンネルと高架、境界で川や道路がずれる）、手直しの口の使い方、名所の建物の作り方。R1〜R8 はこれだけで作業できるようにする

## 性能
都市のセル（松山の中心）・山地・海沿いで、3 指標（ドローコール・三角形・sim＋描画発行）を計測。実在の建物は数が多い区域があるので、07d-1 の段階的な出現の距離で予算に収める。区域のファイルの読み込みと生成の時間も記録する

## 受け入れ基準
- 戦略地図の人口・県境・地名・駅・空港が実在のものに合っている（全国の地図のスクリーンショットと、主要都市 10 か所のセル情報）
- 四国の区域を歩くと、実在の 10km 四方の縮図になっている: 海岸線・川・主要道路・鉄道・町の広がり・山の形・主な施設の位置が、実在の地図と見比べて合う（スクリーンショットと照合を PROGRESS.md に）。隣のセルへ歩いて越えると、川・道路・海岸がつながっている
- 四国以外は今までどおり遊べる。`npm run check`・`npm run build`・`npm run e2e` が通る
- データの利用条件の一覧と、ゲーム内の出典画面がある
