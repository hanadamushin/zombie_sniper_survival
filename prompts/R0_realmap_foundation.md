# R0 実在の日本地図: 基盤

発注者の要望: 「今更ですが、地図は日本の実際のものに合わせたい。出来る限り。都道府県ごと、地方ごとにチャットを分けても良いので頑張ってほしい」

今の地図は、海岸線だけが実データ（world-atlas）で、人口・標高・県境・駅・施設は記憶ベースの合成値、戦術マップ（1km 四方の区域）は乱数で作った地形と町並みです。
あなたの仕事は、**実データから地図を作る仕組み（取得・変換・区域の生成）を作り、1 つの地方で通しで動かすこと** です。残りの地方は R1〜R8 が並行して同じ仕組みで仕上げます。

## 作業の前提（毎回最初に確認。発注者の許可済み）

- このセッションは GitHub リポジトリ `hanadamushin/zombie_sniper_survival` へ**プッシュできる状態**で作業する。作業ディレクトリにリポジトリが無い、または読み取り専用でしか複製できない場合は、**最初に**リポジトリを書き込み権限つき（push）でセッションに追加し、複製してから作業を始めること。**発注者はこの追加とプッシュを事前に許可している**（このプロンプト自体が発注者からの指示）
- 作業の最後に、指定のブランチへプッシュしたうえで、`git ls-remote` でリモートのブランチがローカルのコミットと一致することを確かめてから終える。プッシュできないまま終えない
- **このセッションはクラウド環境「zombie_sniper_survival」で動かす**（国土地理院・e-Stat・国土数値情報へ接続できるのはこの環境だけ）。最初に `curl -s -o /dev/null -w "%{http_code}" https://cyberjapandata.gsi.go.jp/xyz/dem/10/909/403.txt` が 200 になることを確かめ、ならなければ作業を始めずに、環境が違うことを発注者に伝えて終える

## 使うデータ（すべて公的なオープンデータ。外部ファイルの禁止は「モデル・画像・音声」のことで、ビルド時に変換した地図データは `public/data/` に置いてよい）

| 用途 | 出典 | 取り方（確認済み） |

| 標高 | 国土地理院 標高タイル | `https://cyberjapandata.gsi.go.jp/xyz/dem5a/{z}/{x}/{y}.txt`（5m、z15）、`dem/{z}/...`（10m、z14 以下）。欠けている所は `dem` で補う |

## 決めてあること（変えない）
- 戦略地図の 10km 四方のセル、セル番号の振り方、感染シミュレーションの仕組みはそのまま。**中身（人口・標高・土地区分・県・地名）を実データに置き換える**
- 1 つのセルの戦術区域は、そのセルの中の **実在の 1km 四方の窓 1 つ**（約 1024m）。10km を 1km に縮めるのではなく、実在の場所を切り出す
- 窓の選び方: 原則は「セルの中で人口が最も多い 1km メッシュ」（町の中心が出る）。セルに駅・空港・自衛隊の施設があるときは、その施設を含む窓を優先（優先順位を `src/data/` の表に）。人のいないセルは道路があり、平坦な土地の多い窓。選んだ窓の位置（緯度経度）をセルの静的データに持たせ、戦略地図で「区域はここ」と示せるようにする
- 07c の地続き（歩いて隣のセルへ）は残す。隣のセルの窓は実際には離れているので、境界の 120m で地形を混ぜる今の方式を使い、道路は境界の関所でつなぐ（実在の道路の端点に最も近い関所へ寄せる）
- 07b・07d の遊びの約束は守る: 地上で 200m 先の視線が通る割合（田舎 25〜45%、森 15% 未満を目安。実データで外れる場合は、生け垣・藪・林を足して寄せる）、高所の射点 3 か所以上（無ければ鉄塔・給水塔を足す）、本拠の中央 半径 120m の空き地（実在の建物はそこだけ取り除く）

## A. 戦略地図を実データにする（`tools/`、`npm run data`）
- 人口（2020 年国勢調査 1km メッシュ）を 10km セルへ集計して `pop0` に。土地区分は 02 の人口密度の規則のまま、山地は標高と傾斜から
- 標高・海岸・湖（水面）を実データから。海岸線は world-atlas より細かい国土地理院のデータに置き換えてよい（陸のセルの数が変わるなら、セーブの互換は「新規ゲームから」でよいと PROGRESS.md に書く）
- 都道府県・市区町村（N03）、地方。県境付近のセルが隣県になる 02 の不具合を直す
- 町の格（村・町・市・県庁所在地・政令指定都市）、駅（乗降客数から格: 無人・町・市・県庁所在地・政令指定都市）、空港（大中小）、学校・病院・警察・消防の数、自衛隊の施設（国土地理院の地図記号と注記から。陸自の駐屯地の大中小・海自・空自を判別）を、セルの静的データに追加（`StaticCell` へは追加のみ）。07d-3 がこれを使って建物を選ぶ
- 交通ハブ（感染の長距離伝播）を実在の新幹線駅・空港に。海を渡る経路（06）も実在の橋・トンネル・航路に合わせる
- 感染の事前計算（`infection_*.bin`）を新しい人口で作り直す。感染モデルの数値は変えない。90 日目の分布（都市・郊外・田舎・森林のセルの中央値、総数）を変更前後で PROGRESS.md に並べる

## B. 区域のデータ（`tools/real/`、地方ごとに出力）
- 各セルの窓について、標高（4m 間隔に再標本化）・建物の輪郭（種類・推定の階数。高層は注記や「高層建物」の区分から）・道路（中心線と幅）・鉄道と駅・川と水面・施設の点（種類と名前）を取り出し、**決定的な** 小さなバイナリに変換して `public/data/areas/<地方>/<セル番号>.bin` に置く（地方: hokkaido, tohoku, kanto, chubu, kinki, chugoku, shikoku, kyushu。沖縄は kyushu に含める）
- 1 区域の平均 40KB 以下、全国で 120MB 以下を目安（量子化・差分符号化・gzip）。超えそうなら細かい建物（物置）を間引く。大きさの実測を PROGRESS.md に
- ゲームは区域に入るときにそのファイルを読む（07c の Worker で）。ファイルが無いセルは今の乱数の生成に戻る（全国が揃うまで、そして揃った後も保険として）
- 地方ごとに `npm run data:region -- <地方>` で、その地方の取得と変換だけを行えるようにする（R1〜R8 が並行で使う）

## C. 区域の生成を実データ対応に（`src/gen/`）
- 実データがある区域: 地形 = 実標高、道路・鉄道・川・水面 = 実在のもの、建物 = 実在の輪郭の位置と大きさに、07d の建物の種類を当てはめる（当てはめの規則は 07d-3 が詳しく作る。R0 では「輪郭の大きさと区分と施設の注記から、今ある種類（家・コンビニ・雑居ビル・拠点の建物）か、中に入れない箱」で仮置き）
- 植生・藪・草むら・岩は今の方式で、実在の地表（建物・道路・水面以外）に置く。森は国土地理院の土地の区分（無ければ等高線の傾斜と人口）から
- 07c の地続き、ゾンビの配置、探索ポイント、補給箱、潜伏者がそのまま動くこと

## D. 例外と手直しの口（R1〜R8 が使う）
- `tools/data/real/overrides/<地方>.ts` を 8 地方ぶん、空で作る。中身の例: 窓の位置の手動指定、施設の格の訂正、地名の訂正、間引きの強さ。**各地方の担当は自分の地方のファイルだけを触る**
- 名所の建物（任意）: `src/gen/buildings/catalog/landmark_<地方>.ts` を 8 地方ぶん、空で作り、`catalog/index.ts` に登録しておく

## E. 1 つの地方で通す（試験台: 四国）
- 四国（約 190 セル）で、取得 → 変換 → ゲームで歩く、まで通す。松山・高松・高知・徳島の中心、四国山地、しまなみ海道・瀬戸大橋の端、のスクリーンショットを撮り、実在の地形・町並みと見比べて違和感を直す
- 全国のうち四国以外は、R1〜R8 が揃うまで乱数の区域のまま動くこと

## F. 地方担当への手引き
`docs/realmap_guide.md` を書く: 取得と変換のコマンド、キャッシュ、出力の大きさの目安、確認のしかた（どのスクリーンショットを撮り、何と見比べるか）、よくある不具合（窓が海や湖にかかる、急斜面で歩けない、建物が道路に重なる、トンネルと高架）、手直しの口の使い方、名所の建物の作り方。R1〜R8 はこれだけで作業できるようにする

## 性能
都市の窓（松山の中心）・山地・海沿いで、3 指標（ドローコール・三角形・sim＋描画発行）を計測。実在の建物は数が多い区域があるので、07d-1 の段階的な出現の距離で予算に収める。区域のファイルの読み込みと生成の時間も記録する

## 受け入れ基準
- 戦略地図の人口・県境・地名・駅・空港が実在のものに合っている（全国の地図のスクリーンショットと、主要都市 10 か所のセル情報）
- 四国の区域を歩くと、実在の道路・川・建物の並び・地形になっている（スクリーンショットと、同じ場所の実在の地図の特徴の照合を PROGRESS.md に）

- データの利用条件の一覧と、ゲーム内の出典画面がある
