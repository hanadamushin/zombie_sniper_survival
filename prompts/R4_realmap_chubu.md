# R4 実在の日本地図: 中部

R0 が実データから地図を作る仕組み（取得・変換・区域の生成）を作り、四国で通しで動かしました。あなたの仕事は、**中部（新潟・富山・石川・福井・山梨・長野・岐阜・静岡・愛知）のすべてのセルを実データにし、実在の地図と見比べて仕上げること** です。

R1〜R8 は並行して進みます。**自分の地方の出力（`public/data/areas/chubu/`）と手直しのファイル（`tools/data/real/overrides/chubu.ts`）、名所のファイル（`src/gen/buildings/catalog/landmark_chubu.ts` と `src/gen/buildings/defs/landmark/chubu/`）だけ** を触ってください。仕組みそのもの（`tools/real/` の共通部分・`src/gen/`）に直したい不具合を見つけたら、最小限の修正にとどめ、PROGRESS.md に「共通部分を直した」と明記してください（取りまとめ役が他の地方との衝突を解きます）。

## 作業の前提（毎回最初に確認。発注者の許可済み）

- このセッションは GitHub リポジトリ `hanadamushin/zombie_sniper_survival` へ**プッシュできる状態**で作業する。作業ディレクトリにリポジトリが無い、または読み取り専用でしか複製できない場合は、**最初に**リポジトリを書き込み権限つき（push）でセッションに追加し、複製してから作業を始めること。**発注者はこの追加とプッシュを事前に許可している**（このプロンプト自体が発注者からの指示）
- 作業の最後に、指定のブランチへプッシュしたうえで、`git ls-remote` でリモートのブランチがローカルのコミットと一致することを確かめてから終える。プッシュできないまま終えない
- **このセッションはクラウド環境「zombie_sniper_survival」で動かす**（国土地理院・e-Stat・国土数値情報へ接続できるのはこの環境だけ）。最初に `curl -s -o /dev/null -w "%{http_code}" https://cyberjapandata.gsi.go.jp/xyz/dem/10/909/403.txt` が 200 になることを確かめ、ならなければ作業を始めずに、環境が違うことを発注者に伝えて終える

## 読むもの
- `CLAUDE.md`、`docs/PROGRESS.md`（R0 の節）
- **`docs/realmap_guide.md`（必読）**

## 作業
1. `npm run data:region -- chubu` で取得と変換。キャッシュは `tmp/realdata/`（取得は 1 秒あたり 5 件まで）
2. 全セルの区域を生成して、手引きの自動点検（歩ける、境界で地形・川・道路がつながる、射点、視線の割合、本拠の空き地、建物と道路の重なり、大きさ）を通す。外れたセルは手直しのファイルで直す
3. **実在の地図と見比べる**: 次の場所の区域に入ってスクリーンショットを撮り、海岸線・川・主要道路・鉄道・町の広がり・駅や施設の位置・山の形が、実在の 10km 四方を 1/10 に縮めたものとして合っているかを確かめる。合わない点を直し、照合の結果を PROGRESS.md に表で残す
   - 名古屋（政令指定都市）・新潟・静岡・浜松、中部国際空港、北アルプス・富士山の周り、陸自の守山・富士の周辺、空自の小松・浜松、佐渡航路
4. 戦略地図で、地方の県境・地名・駅・空港・自衛隊の施設が正しいか確かめる
5. 名所（任意・3 つまで）: その地方を代表する建物を 07d の設計図の形で作る（例: 城、タワー、大きな寺社、橋の塔）。中に入れなくてよい（外観だけで、登れる展望台があれば射点にしてよい）。三角形の上限は 07d の手引きの「ビル 25 階以上」と同じ。実在の位置を縮めた場所に置く

## 性能
その地方で最も建物の多い区域・山地・海沿いで 3 指標を計測し、予算（ドローコール < 150、三角形 < 50 万、sim＋描画発行 < 4ms）を超えたら手引きの間引きで収める

## 受け入れ基準
- 地方のすべてのセルに区域のデータがあり、自動点検をすべて通る（例外は理由つきで PROGRESS.md に）
- 上の照合の場所すべてでスクリーンショットを撮り、実在との照合結果が PROGRESS.md にある
- 出力の大きさ（地方の合計・1 区域の平均と最大）を記録。地方の合計が手引きの目安以内
- `npm run check`・`npm run build` が通る。e2e は区域の読み込みに関係する spec だけでよい（全件は取りまとめ役が回す）

## 終わりに
`CLAUDE.md` の「終わる前にやること」を実行。他の地方の担当に役立つ発見（手引きの不足、共通部分の不具合）は `docs/realmap_guide.md` の末尾「各地方からの追記」に 1 行ずつ足してください。

## R0 からの注意（R0 が追記）
- 手引き `docs/realmap_guide.md` の 9 節のチェックリストがそのまま作業の順番。取得は `npm ci` の後に `npm run data:region -- <地方>`（四国 207 セルで取得 約 3,000 件・約 10 分。途中で止めても再開できる）、点検は `node tools/real/check.ts <地方>`
- 戦略地図（`public/data/grid.json`・`infection_*.bin`）は R0 が全国ぶん実データで作り直し済み。**R1〜R8 は `npm run data` を回さない**（全地方で同じファイルを書き換えて衝突する）。警察・消防・自衛隊の数は地方の `index.json` からゲームが起動時に読む
- 共通部分（`tools/real/` の lib・region.ts、`src/gen/real/`、`src/data/realmap.ts`）を直したら PROGRESS.md に「共通部分を直した」と明記。区域ファイルの形（`src/gen/real/format.ts`）を変えると全地方の作り直しになるので、変えずに済む方法を先に考える
- R0 の仮置き: 施設は箱（07d-3 が種類を当てはめる）、橋は土手、トンネルは描かない、陸自の駐屯地は小（`base.jgsdf_s`）だけ。名所を置くには `layoutReal` に 1 行足す（手引き 7 節）
