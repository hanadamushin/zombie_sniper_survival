# 10 スマホ対応（任意・低優先）

あなたはスマートフォン（タッチ操作）対応の担当です。PC 版が完成している前提で、
**PC 版の挙動を一切変えずに**、タッチでも一通り遊べるようにします。完璧な操作性よりも「破綻なく遊べる」を目標に、小さくまとめてください。

## ゴール（M8）
スマホの横画面で、狙撃・回収・指揮・地図の全操作ができる。

## 実装範囲
1. **入力層**: タッチ入力から同じ `InputFrame` とコマンドを生成する（sim 側は変更しない）。端末判定はポインタ種別で行い、PC とは自動で切り替える
2. **戦術層の操作**
   - 左: 仮想スティック（移動）／右: ドラッグで視点
   - ボタン: スコープ（トグル）、射撃、息止め（押している間）、リロード、姿勢切替、ナイフ、回収
   - スコープ中の視点感度は倍率に応じて下げる。微調整用に **ジャイロ照準**（任意でオン、許可ダイアログ対応）
   - 倍率はスライダー、ゼロインは ± ボタン
   - 照準補助は入れない（狙撃の手応えを保つ）。代わりに息止めの効果時間をタッチ時のみ +30%
3. **指揮層・戦略層**: ピンチでズーム、ドラッグでパン、タップで選択、長押しで詳細。壁・堀の線引きはドラッグ。パネルは下からのシート表示
4. **レイアウト**: 横画面固定の案内（縦のときは回転を促す）、セーフエリア対応、ボタンは 44px 以上
5. **性能**: 画質プリセット「低」（視程 500m、草なし、同時ゾンビ 60、解像度スケール 0.75）を自動適用。設定で変更可
6. **PWA（余力があれば）**: manifest とアイコン（コード生成）、全画面表示

## やらないこと
- ゲーム内容・バランスの変更、PC 操作の変更、ネイティブアプリ化

## 受け入れ基準
- Playwright のモバイルエミュレーション（横向き）で、新規ゲーム → 1体狙撃 → 耳回収 → 指揮層で柵を1本配置、が通る
- PC での `npm run check` と e2e が引き続き通る（PC の挙動が変わっていない）
- モバイル相当の設定で 30fps 以上（計測値を PROGRESS.md に）

### 06 の結果を受けて

- 建築の操作はマウス前提（`ui/command/build.tsx` の `BuildGround`: 左ドラッグで連続配置／視点移動、右ドラッグで回転、ホイールで拡大）。Pointer Events で書いてあるので、1 本指 = 配置・移動、2 本指 = 回転・拡大の対応を足せる。幅 360px でも崩れないことだけ確認済み

### 07c の結果を受けて

- ゾンビは区域あたり最大 600 体、周囲 3×3 の区域を描画している。画質プリセット「低」では、同時出現の倍率（`BALANCE.world.activeMul`）ではなく **描画側** を絞る（遠くのゾンビの簡略化しきい値 `RENDER.zombies.lodPixels` を上げる、隣の区域を描く距離 `RENDER.terrainLod` を縮める、視程を 500m に）。sim の数を端末で変えると、同じセーブで遊びが変わるため
- Web Worker（`render/tactical/mapWorker.ts`）で隣の区域を作っている。iOS Safari での Worker と転送の動作を確認すること

### 08 の結果を受けて

- HUD の部品は画面の縁に寄せてあり、ポインタを受けるのは `#ui button` だけ。幅 480px 以下で上部バーが 2 段（`--hud-h: 64px`）。タッチのボタンはこのデザイントークン（`ui/styles.css` 冒頭の CSS 変数）で作る
- 毎フレーム動く表示は `ui/live.ts` の `useLive`（Preact を通さない）。仮想スティックやゲージもこの仕組みに載せる
- 音は最初にキー／ボタンを**離した**ときに AudioContext を作る。タッチでは `touchend` / `pointerup` で同じ処理を呼ぶ（iOS は利用者の操作の中でしか音を始められない）
- 設定画面（`zss.settings.v1`）に、タッチ用の感度とジャイロのオン／オフを足す
- 07e で賃金が小数（0.1 刻み、例「賃金 0.9/日」）になった。狭い画面の生存者の行で桁が増えても崩れないか確認する

## 07d-1 からの注意
- 中に入れる建物の描画は 1 区域で最大 7 ドローコール（`render/tactical/enterables.ts`）。内部を出す距離 `RENDER.enterables.near`（40m）と外観の距離 `mid`（300m）が三角形を決める。端末が重いときはこの 2 つを下げる
- 屋内は天井が低く狭い。タッチの視点操作で壁に寄りすぎないよう、カメラの near（0.1m）と人の半径（0.35m）の関係はそのまま保つこと

## 07d-2a からの注意
- 狭小 3 階建て・アパートの階段は幅 0.9m の折り返し、木造アパートの外廊下は内幅 1.14m。タッチの移動で壁に引っかかりやすい場所なので、仮想スティックの微調整（低速）を確かめる

## 07d-2b からの注意
- ビジネスホテル（10 階）の折り返し階段は 9 回上り下りする。タッチの移動で階段の踊り場に引っかからないか確かめる。回転寿司の通路（幅 1.8〜1.9m）とコンビニの通路（1.2〜1.4m）はブースや棚に挟まれて狭い

## 07d-2c からの注意
- 超高層（32 階）は折り返し階段を 32 回上る。タッチの移動で踊り場の角に引っかからないか、上り続ける操作が辛くないか（自動で上る補助を検討）を確かめる。百貨店の止まったエスカレーター（幅 1.0m の直階段）は両脇に手すりがある
- 内部の三角形は入れる階で 1 階あたり最大 2,800 前後（百貨店・庁舎風・商業ビル）。`RENDER.enterables.near` を下げると端末の負担が減る
