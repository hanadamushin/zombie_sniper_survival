# 07b 実機プレイの指摘への対応

発注者が Windows ノート PC（RTX 5060、タッチパッド）で初めて実際に遊びました。
描画は屋外で 165fps 出ており性能は問題ありません。揺れの強さも「問題ない」との評価です。
あなたの仕事は、そのとき出た指摘を直すことです。新しいシステムは作らず、下の A〜G だけを確実に仕上げてください。

## 読むもの
- `CLAUDE.md`、`docs/PROGRESS.md`（特に 03・04・05 の節）
- `src/input/**`、`src/gen/**`、`src/data/tactical.ts`、`src/render/tactical/zombies.ts`、`src/sim/colony/` の潜伏者（hideouts）まわり

## 実装範囲

### A. マウスなしでも狙撃できる操作（最優先）
指摘: 「ノート PC でマウスが無いと、スコープを覗きながら撃てない」。タッチパッドでは右ボタンを押したまま左クリックができない。

- **スコープの切替キー Q**（押すたびに覗く／戻す）。右クリック押下の方式はそのまま残す
- **射撃キー F**（押している間 `fire`）。左クリックもそのまま
- **矢印キーで照準を動かす**（今は WASD と重複して移動に割り当てられている。移動は WASD だけにする）。スコープ中は倍率に応じて遅くし、押し始めはゆっくり・押し続けると加速、で微調整できるようにする。Windows のタッチパッドはキーを押している間カーソル移動を止めることがあるため、キーだけで狙って撃てることが必要
- **倍率キー `-` / `=`**（ホイール・2 本指スクロールも従来どおり）
- いずれも `input/bindings.ts` に置き、`InputFrame` の形は変えない（`scope` / `fire` / `lookDX` / `lookDY` / `zoomDelta` に載せる）
- 画面下のヒントと一時停止メニューの操作一覧に新しいキーを出す
- e2e: マウスを一切使わず、キーだけで「スコープ → 照準 → 息止め → 射撃 → 命中」が射撃場で通ること

### B. マウス感度
指摘: 「問題ないが、もう少し速くてもよい」。既定の視点感度を 25% 上げる（通常時・スコープ中とも）。値は `src/data/**` に置く。設定画面は 08 が作るので、ここでは既定値だけ。

### C. 射撃場への入口
指摘: 「射撃場がどこかわからない」。タイトル画面と一時停止メニューに「射撃場」ボタンを足す（`?range=1` と同じものを開く）。射撃場から本編・タイトルへ戻れること。

### D. 地形の遮蔽と緊張感（開始地点になる rural / forest を中心に）
指摘: 「少し退屈。建物や地形の凹凸、木々が少なく、遠くから見えてしまって緊張感が薄れる」。耳を拾いに歩く時間が退屈、という話の主因でもある。

狙いは **「地上を歩いているときは見通しが切れ、高所の射点に登ったときだけ遠くまで見える」** こと。
- rural: 起伏を増やす（小さな丘・窪地・土手・段々の田畑）、田畑の境の生け垣や防風林、屋敷林、竹やぶ、背の高い草むら・葦、点在する納屋・廃車・ビニールハウスの骨組みなど、視線を切るものを増やす
- forest: 下生えと倒木・岩で近距離の見通しを切る。林道と沢筋は射線として残す
- suburb / urban / mountain は大きく変えなくてよい（見た目の密度が足りない場所があれば足す）
- ゾンビの初期配置を、開けた場所の真ん中ではなく遮蔽物の近く・建物の陰・窪地に寄せる（`sim/tactical/zombies.ts` の配置）。歩いていて不意に近距離で出くわすことがある状態にする
- **数値で確認する**: 「地上（目の高さ 1.7m）でランダムに選んだ 200m 離れた 2 点の間に視線が通る割合」をテストで測る。目標は rural 25〜45%、forest 15% 未満。03 の値を先に測って PROGRESS.md に前後を書く。あわせて「高所の射点 3 か所以上」「射点から 300m 以上見渡せる」は維持する（既存テスト）
- 樹冠は視線を通す判定のままなので、見通しを切る役は幹・生け垣・地形・建物・草むら（ゾンビの視認を割り引く既存の仕組み）で作る。プレイヤーの目に対しては描画上ちゃんと隠れること（スクリーンショットで確認）
- 予算は厳守: ドローコール < 150、三角形 < 50 万（forest は今 37 万なので注意）、マップ生成 1 回 150ms 未満
- 同じシードで地形が変わるので、決定的生成のテストは通るが見た目は別物になる。セーブ互換は「地形は再生成される」ので問題ないが、建築済みの本拠（中央 半径 120m の平坦地）は変えないこと
- 歩行が遅すぎると感じるなら `TACTICAL.player` の歩き 1.6 m/s を上げてよい（上限 2.4。走り 5.0 とスタミナとの差は残す）。変えたら `02_systems_spec.md` §3.6 も直す

### E. 生存者を見つけられるようにする
指摘: 「生存者はまだいない？ 見つけられなかった」。実装はあるが、探索ポイントに近づかないと気づけない。

- 新規ゲームの開始セルには、本拠の中心から 250〜450m の範囲に潜伏者が必ず 1 人いるようにする（セルの H が足りなくても最初の 1 人は保証）
- 潜伏者のいる場所から **細い煙** を立てる（昼は遠くから見える、夜は小さな灯り）。射点から見渡すと「あそこに誰かいる」と分かるように
- HUD の「人の気配」は距離だけでなく方角も出す（04 の「未回収の死体」と同じ出し方）
- 会話 → 候補リスト → 指揮層（Tab）で雇う、の流れが初見で分かるよう、会話直後に 1 行の案内を出す（本格的なチュートリアルは 08）

### F. ゾンビの腕の向き
指摘: 「ゾンビの手が背中側を向いている（前後逆）かもしれない」。`render/tactical/zombies.ts` で腕が進行方向へ伸びているか、4 種類すべてと這行・転倒・死体を横と斜め上からのスクリーンショットで確認して直す。顔・足の向きと移動方向が一致していることも合わせて確認する。

### G. タイトル
指摘: 「『耳の国』はやめる。タイトルは別途考える」。
- 画面・`index.html` の `<title>`・README・docs から「耳の国」を外し、決まるまでの仮題を **Zombie Sniper Survival** だけにする
- 表示名は `ui/i18n/ja.ts` の 1 か所を変えれば全体に反映されるようにしておく（後で正式名に差し替える）

## やらないこと
新しいゲームシステム、バランスの全体調整（09）、見た目の統一と音（08）、タッチ操作（10）。

## 受け入れ基準
- マウスを使わず、キーボードだけで射撃場の 200m 標的に命中させられる（e2e）
- タイトル画面から射撃場に入れて、戻れる
- rural と forest の「200m で視線が通る割合」が目標の範囲に入り、変更前後の値が PROGRESS.md にある。射点からの眺望と地上からの眺めを、変更後のスクリーンショットで自分の目で確認した
- 新規ゲームを 3 シードで始め、射点か地上から煙が見え、歩いて会いに行って雇える
- ゾンビ 4 種の腕・顔・足が進行方向を向いている（スクリーンショット）
- どこにも「耳の国」が残っていない（`git grep` で確認。PROGRESS.md の過去の記録は除く）
- `npm run check`・`npm run build`・`npm run e2e` が通り、性能 3 指標が予算内

## 終わりに
`CLAUDE.md` の「終わる前にやること」を実行。08・09 向けの注意があれば各プロンプトの末尾に追記してください。
