# 06 建築・防衛・駐屯地

あなたは拠点の建築（壁・堀・建物）、ゾンビの襲来、防衛戦、そして各地の駐屯地の担当です。
**「堀と壁でゾンビの流れを設計し、見張り塔から狙撃で仕留める」** という、このゲームの2つの柱が交わる場面を作ります。

## 読むもの
- `CLAUDE.md`、`docs/PROGRESS.md`（04・05 の引き継ぎは必読）
- `docs/02_systems_spec.md` §6・§7・§8、§3.4（フローフィールド）、§4.5
- `docs/01_game_design.md` §10・§11
- `docs/04_architecture.md` §5（`BuildState`, `Structure`, `Outpost`）、§7

## ゴール（M4）
指揮層で設計図を置くと建築担当が建て、夜にゾンビが押し寄せ、壁が削られ、堀が流れを曲げ、プレイヤーが塔から迎撃できる。
掃討したセルに駐屯地を置き、弾薬を補給できる。

## 実装範囲

### A. 指揮層と設計図（`src/ui/command/build.tsx`, `src/sim/build/blueprints.ts`）
- Tab で俯瞰カメラ（パン・ズーム・回転）。4m グリッドのスナップ、配置可否の表示
- 壁・堀は **ドラッグで線状に連続配置**。建物は占有サイズつきで回転配置
- `placeBlueprint` / `cancelStructure` / 優先度変更 / 解体
- 定義は `data/buildings.ts`（§6.1・§6.2 の全項目。解禁条件は技術IDで持たせ、判定関数は 07 が差し込めるよう `isUnlocked(defId, state)` を1か所に）。07 完成まではデバッグフラグで全解禁できるように

### B. 建設（`src/sim/build/construction.ts`）
- 05 が公開した建築 output の受け口を実装: 優先度順に資材搬入 → 工数消化 → 完成。修理、堀の清掃も建築タスク
- 完成・破壊で `gridRev` を上げる

### C. 構造物の機能
- 壁・門: 耐久、ゾンビの攻撃で減少、0で破壊（瓦礫を一定時間残す）。門は生存者が通れる
- 堀: ゾンビ通行不可。縁に来たゾンビは堀沿いに移動。死体の蓄積 → 8体で通行可 → 清掃で復旧
- 見張り塔: プレイヤーが登れる射点。防衛担当の配置場所
- 有刺鉄線、跳ね橋など技術依存のものもデータと挙動を実装（解禁は 07）
- 機能建物: 住居の収容、倉庫の容量、農地・畜舎・温室の生産、工房・研究所・診療所・食堂などの係数を 05 のシステムへ反映（05 の「仮の畑」「手作業」を正式な建物参照に置き換える）
- 司令部: 新規ゲーム時に本拠セル中央へ自動設置。破壊で `defeat`

### D. フローフィールド（`src/sim/build/flowfield.ts`）
- 4m グリッド 256×256、目標 = 司令部（および生存者のいる建物）。Dijkstra
- コスト: 平地 1、壁・門 = `1 + 耐久/20`（壊して通るほうが近ければ壊す）、堀 = 通行不可（死体で埋まれば 3）、有刺鉄線 +4
- `gridRev` 変更時のみ再計算（5ms 未満）。04 のゾンビ移動に「本拠セルではフローフィールドに従う」を接続
- **テストで確認**: 堀で囲って1か所だけ開けると全ゾンビがそこへ向かう／完全に囲うと最も弱い壁へ向かう／堀が埋まると渡る

### E. 襲来（`src/sim/build/raids.ts`）
- 夜間接近と大群（§7）。02 が積んだ `hordeMeter` を使う。警告イベント（方角・規模の目安・到着時刻）
- 120体超は波状に投入
- 襲来時の生存者: 05 の AI に「避難」「持ち場へ」を指示する口を呼ぶ
- 防衛担当の戦闘（§4.5）: 武器別の射程・命中・発射間隔、塔ボーナス、翌朝の耳自動回収

### F. 駐屯地（`src/sim/world/outposts.ts`）
- `foundOutpost` コマンド（§8 の条件）、等級アップ、常駐者の配置
- 日次補給、`resupply`（プレイヤーが駐屯地/本拠で弾薬を受け取る）、ファストトラベル
- 駐屯地への襲来の数値判定、陥落
- 駐屯地セルの戦術マップ中央に簡易プレハブ（柵・テント・弾薬箱・旗）を配置
- 戦略地図への表示（02 の UI に追加）

### G. 描画
- 全構造物のローポリ表現（材質ごとに見た目が明確に違うこと）、建設中の半透明/足場表現、耐久低下のひび・傾き、堀の死体の溜まり具合
- InstancedMesh で壁 2,000 タイルまで軽く描ける

## 設計上の注意
- 「壁で完全に囲めば安全」にならないこと（門が必要、大群は壁を壊す）。「堀だけで完封」にもならないこと（死体で埋まる、掘るのが遅い）
- 防衛担当だけで大群を完封できない強さに。プレイヤーの狙撃が戦況を左右する余地を残す。特に肥大型は防衛担当では止めにくくする

## やらないこと
技術の解禁処理・研究 UI（07）、音、チュートリアル。

## 受け入れ基準
- 木柵で囲い、門と塔を建て、夜の接近を塔から迎撃できる
- 堀で入口を1か所に絞ると、ゾンビがそこに列をなし、貫通狙撃が決まる
- 放置した壁が大群に破られ、司令部が壊されて敗北画面になる
- 掃討した隣接セルに駐屯地を置き、そこで弾薬を補給できる
- フローフィールドと襲来のテストが `npm run check` に入っている
- 襲来 120 体＋生存者 30 人＋壁 500 タイルで 60fps 相当（計測値を PROGRESS.md に）

## 追加の指示（01・02 の結果を受けて）

- **海を渡る経路を足す（F に含める）。** 現状の移動は陸続きのみで、本州から北海道・四国・九州へ行けない。開始地点は北海道や九州にもなり得るので、このままだと建国条件「駐屯地6か所・3地方以上」（07）を満たせない開始地点がある。青函・関門・本四（3ルート）などを固定リンクとしてデータで持ち、`findRoute` と戦略地図に反映する（所要時間は通常のセル移動より長め）。ゾンビの拡散はリンクを渡らないままでよい。`npm run data` で再生成し、テスト「どの開始候補からも3地方以上に到達できる」を足す
- `hordeMeter` は 02 が毎日「本拠セルへのゾンビ流入数」を加算している（`infectionStepped{homeInflow}`）。襲来で消費したぶんを減らすのは本セッション
- 駐屯地の誘引は 02 の `settlementAttraction` が `outposts[].garrison` の人数から既に計算している。`Outpost` を正しく作れば感染側の対応は不要
- 掃討判定は `derive.ts` の `isCleared`、防衛や駐屯地の数値戦闘で倒したぶんは `removeZombies` で減らす（戦術マップ上の撃破は `zombieKilled` 経由で自動）
- 戦略地図は `src/ui/world/`（`MapCanvas.tsx`, `WorldMap.tsx`）。駐屯地・ファストトラベルの表示と操作はここに足す
### 03 の結果を受けて

- **プレイヤーが本拠にいないときの襲来を決める。** 戦術マップはプレイヤーのいるセルにしかないので、不在・移動中は本拠の壁もゾンビも実体がない。不在時の襲来は駐屯地と同じ数値判定で解決し（壁の耐久・防衛担当・堀を係数にして、壁の損傷・死傷・撃破数を出す）、帰還時に `BuildState` の結果が見える形にする。在席時の実戦と結果が極端にずれないことをテストする
- フローフィールドは 03 の `map.walk`（静的）に `BuildState` の構造物を重ねて作る。本拠セルは中央 半径 120m が平坦な空き地（建築用地）。その外側に建てる場合は既存の建物・樹木と重ならないことを配置可否に含める
- 03 のプレイヤーは 0.5m までの段差を乗り越える。壁・柵はそれより高い当たり判定にし、見張り塔は 03 のはしご／階段の仕組み（`gen/builder.ts` の `addTower` / `addStairs` と同じ形のデータ）で登れるようにする
- 04 でゾンビは外階段を登れるようになっている。見張り塔ははしごなので登られない、という区別を保つ
