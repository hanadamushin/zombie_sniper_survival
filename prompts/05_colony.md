# 05 生存者・経済

あなたは生存者コミュニティ（雇用、ステータス、仕事、士気、経済、調達遠征）の担当です。
プレイヤーは個々に細かく命令せず、**「誰に何を任せるか」だけ決めれば共同体が自律的に回る** のが理想です。

## 読むもの
- `CLAUDE.md`、`docs/PROGRESS.md`
- `docs/02_systems_spec.md` §4・§5、§1
- `docs/01_game_design.md` §8・§9
- `docs/04_architecture.md` §5（`ColonyState`, `Survivor`, `Expedition`）、§6

## ゴール（M3）
生存者を見つけて雇い、仕事を割り振ると、毎日の賃金・食料・生産が回り、調達隊が物資を持ち帰る。
放置しても破綻の原因がログと台帳から読み取れる。

## 実装範囲

### A. 生存者（`src/sim/colony/survivors.ts`）
- 生成（§4.1）: 4ステータス、賃金、特性（`data/traits.ts` に12種類ほど）、日本人名のランダム生成
- 雇用候補の発生: セルの `H` から。戦術マップ上の探索ポイントで遭遇（E で会話 → 候補リストへ）、調達隊が連れ帰る
- `hire` / `dismiss` コマンド、契約金

### B. 仕事と行動AI（`src/sim/colony/jobs.ts`, `ai.ts`）
- 仕事: 農業・防衛・調達・建築・研究・工作・医療・待機
- 作業量の式（§4.2）。1日の稼働時間と、食事・睡眠のスケジュール
- **ルールベースAI**: 仕事ごとの状態機械。本拠にいる生存者は「作業場所へ歩く → 作業 → 食事 → 就寝」を 4m グリッド上で移動（経路は簡易 A* か直線＋回避でよい）。作業の成果自体は時間あたりの数値加算で、アニメーションの進行とは独立させる（倍速でも結果が変わらないように）
- 建築・防衛・研究の **成果の受け口** は用意するが、中身は 06・07 が実装する。ここでは「建築 output を BuildState の建設待ちに配る関数」「研究 output を返す関数」「防衛担当の一覧を返す関数」を公開し、建物が無い間は仮の作業場所（司令部周辺）で働く
- 農業: 農地が実装されるまでは「仮の畑」1区画を司令部横に置いたものとして生産させる

### C. 経済（`src/sim/colony/economy.ts`）
- 資源の備蓄・容量。毎朝の賃金支払い（不足時は能力の高い順に未払い）、食料消費
- 食料市場: 農業担当の生産 → 売り出し → 共同体が価格式（§5）で購入。中立農村からの購入（`buyFood`）
- 工作: 弾薬製造（工房が無い間は効率 50% の手作業）
- 台帳（直近30日）とログ

### D. 士気・健康（`src/sim/colony/morale.ts`）
- §4.3 の増減、離反、負傷・感染の経過、死亡
- プレイヤー死亡時の復帰処理（3日経過、所持品喪失、司令部で再開）と、共同体不在時の敗北

### E. 調達遠征（`src/sim/colony/expeditions.ts`）
- `sendExpedition` コマンド、所要時間、帰還判定（§4.4）、収穫、セル loot の消費、生存者の連れ帰り
- 結果は読み物として面白いログにする（誰が何を見つけ、誰が戻らなかったか）

### F. 描画と UI
- 本拠セルにいる生存者の描画（04 のゾンビと同じインスタンス方式、色と姿勢で区別。仕事ごとに持ち物の簡易表現）
- 指揮層パネル: 生存者一覧（ステータス、賃金、士気、状態、仕事のドロップダウン）、雇用候補、経済台帳、遠征の編成と進行状況、ログ
- パネルは機能優先でよい（見た目の統一は 08）

### G. テスト
- 30日間ヘッドレスで回して収支・備蓄が台帳と一致
- 賃金式・作業量式・帰還率式の境界値
- 未払い → 士気低下 → 離反の流れ
- 速度 x1 と x10 で1日の生産量が一致（許容誤差 1%）

## やらないこと
建築物そのもの、襲来、技術ツリー、駐屯地。

## 受け入れ基準
- 新規ゲームから: 探索で生存者に会う → 雇う → 農業と調達に割り振る → 数日後、食料と物資が増え、賃金が引かれている
- 耳が尽きると未払いになり、士気が下がり、やがて離反する
- 遠征が武器の違いで帰還率に差が出る（テストで統計的に確認）
- 生存者 60 人でもコロニー更新が 1 tick あたり 1ms 未満

## 追加の指示（01・02 の結果を受けて）

- **セルの H は 02 では減らない。** 候補として出した／雇った／遠征が連れ帰った人数ぶん `world.cells.H` を減らす（H が残るとゾンビを引き寄せ続ける）。候補の人数はそのセルの H を上限にする
- 遠征は 02 の関数を使う: 経路と所要時間は `sim/world/travel.ts` の `findRoute`、危険度は `derive.ts` の `dangerOf`、討伐数の反映は `removeZombies(state, cell, n)`、物資は `world.cells.loot` を減らす（戦術マップの探索ポイント数も loot から決まる）。陸続きでないセルは経路なしになるので、編成 UI で選べないようにする
- 拠点の人数は 02 の `settlementAttraction` が毎日読んで、本拠へのゾンビ流入（`hordeMeter`）に反映している。`Survivor.status` / `location` を正しく保つこと
- プレイヤーが移動中（`world.travel` あり）や本拠以外のセルにいる間も、共同体の時間は進む（移動中は x30 の早送り）。「x1 と x10 で生産量が一致」のテストに x30 も加える
### 03 の結果を受けて

- **戦術マップがあるのはプレイヤーのいるセルだけ**（`areaOf(state)`。移動中は `state.tactical = null`）。生存者の歩行・作業アニメーションはプレイヤーが本拠セルにいるときだけ動かし、不在・移動中は位置の更新を止めて数値の加算だけを続ける。どちらでも1日の成果が一致することをテストする（G の x1 / x10 のテストと同じ枠）
- 拠点内の移動は `map.walk`（4m 通行グリッド）と `isWalkable` を使う。本拠セルの中央 `map.spawn.home` の半径 120m は平坦な空き地で、司令部・仮の畑はここに置く
- 探索ポイントは `map` の探索ポイント（扉の前の座標）と `state.tactical.lootSpots`。建物の中には入れない

### 04 の結果を受けて

- **死亡後の復帰**: 04 の仮実装（`sim/tactical/combat.ts` の `revive`: 4 秒後にその場の区域で復帰、耳 0・弾 40）を D の規則に置き換える。本拠以外で死んだ場合は本拠セルへ戻す（`player.cell` を本拠に、`world.travel` を解除）
- **弾薬の流れを通す**: 04 は開始時の弾 100 発をプレイヤーの所持に置き、備蓄は 0。この配分のままでよい。工作で作った弾は備蓄へ入り、プレイヤーは本拠で `resupply` コマンド（`sim/tactical/index.ts` に口だけある）で備蓄から所持へ移す。所持上限を `BALANCE` に置く。**本拠での `resupply` は本セッションで実装する**（駐屯地での補給は 06）。これが無いと 05 完了時点で弾が尽きたら詰む
- 耳の流れも同様に決める: プレイヤーの `player.inv.ears` を本拠で備蓄（`colony.stock.ears`）へ納める操作（本拠に戻ったら自動でよい）。賃金は備蓄から払う
- 生存者の描画は 04 のゾンビと同じ箱の InstancedMesh＋接地影の方式に合わせる（`render/tactical/` のゾンビ描画を参照）。遠目にゾンビと見間違えない色・姿勢にする（誤射防止）
- 時間の対応は「実時間 1 秒 = ゲーム内 1 分」。04 の感染は 48 ゲーム時間で死亡なので、医療担当・医薬品による治療をここで接続する
- ヘッドレスではポインタロックが取れない。e2e の操作は `window.__game.debug.setInput(...)` を使う
