# 実在の日本地図: 地方担当（R1〜R8）の手引き

R0 が作った「実データから区域を作る仕組み」で、自分の地方のすべてのセルを仕上げるための手引き。
**これだけ読めば作業できる** ように書いてある。分からないことがあれば R0 の PROGRESS.md の節を見る。

## 1. 全体の形（覚えておくこと）

- 戦略地図の 1 セル = 実在の **10km 四方**（等距円筒図法の格子。セル番号 = `gy × 167 + gx`）
- 戦術区域（1024m 四方）= そのセルの 10km 四方を **水平に 1/10** に縮めたもの。北西の角が (0, 0)、x 東・z 南、区域の 1m が実在の約 10m
- **縮めるのは位置と広がりだけ**。人・建物・道路の幅・木は実寸。だから実在の建物を 1 棟ずつ写すのではなく、土地利用と人口から町並みを **生成** する
- 高さは別の縮め方（`src/data/realmap.ts` の `REAL_AREA.height.knots`。海の近くで 1/4.5、山で 1/13 程度）。急すぎる斜面を歩けるようにするため
- 隣り合うセルの区域は実在でも隣り合う。**辺の上の標高・土地利用は両側で同じ点を標本化している** ので、地形・水面・道路は境界で必ず一致する（一致しなければ不具合）

```
tools/real/
  region.ts        npm run data:region -- <地方>        取得 → 変換 → public/data/areas/<地方>/
  check.ts         node tools/real/check.ts <地方>      全セルの自動点検（4 節）
  area-preview.ts  node tools/real/area-preview.ts <地方> <セル>   データそのものを上から（土地利用・道路・施設）
  area-map.ts      node tools/real/area-map.ts <セル> [--home]     ゲームが作る区域を上から（1px = 1m）
  estimate.ts      npm run data:region -- <地方> --estimate      取得枚数の見積もり（全国も）
  grid.ts          npm run data                         戦略地図（全国。R1〜R8 は原則触らない）
  lib/             取得（キャッシュ・間隔）、zip、ベクトルタイル、標高タイル、シェープファイル、L03-b
tools/data/real/overrides/<地方>.ts   手直しの口（6 節）
src/gen/real/format.ts                区域ファイルの形（読み書き）
src/gen/real/layout.ts                区域の生成（地形・水・道路・町並み・施設）
src/data/realmap.ts                   すべての数値（高さの縮め方、町の格、施設の大きさ、点検のしきい値）
src/gen/buildings/catalog/landmark_<地方>.ts / defs/landmark/<地方>/   名所の建物（7 節）
src/data/landmarks/<地方>.ts           名所の置き場所の表（7 節）
```

地方とセル: 都道府県から決まる（`tools/real/lib/regions.ts`）。hokkaido / tohoku / kanto / chubu / kinki / chugoku / shikoku / kyushu（沖縄は kyushu）。

## 2. 取得と変換

1. 環境の確認: `curl -s -o /dev/null -w "%{http_code}" https://cyberjapandata.gsi.go.jp/xyz/dem/10/909/403.txt` が 200（クラウド環境「zombie_sniper_survival」でだけ通る）
2. `npm ci`（world-atlas などが要る）
3. 見積もり: `npm run data:region -- <地方> --estimate`（R0 の実測は下の表）
4. 本番: `npm run data:region -- <地方>`。**途中で止めても再開できる**（ダウンロードは `tmp/realdata/` にキャッシュ。2 回目からはほぼオフライン）
5. 一部のセルだけ作り直す: `npm run data:region -- <地方> --cells 21757,21758`（index.json は他のセルを保ったまま更新）

| 地方 | セル | DEM z12 | ベクトル z13 | 注記 z14（町だけ） | L03-b zip | 合計（見積もり） |
|---|---|---|---|---|---|---|
| hokkaido | 919 | 1833 | 6936 | 〜8300 | 33 | 17143 |
| tohoku | 725 | 1335 | 5120 | 〜7300 | 24 | 13823 |
| kanto | 341 | 630 | 2351 | 〜5900 | 13 | 8892 |
| chubu | 713 | 1312 | 4908 | 〜8800 | 27 | 15056 |
| kinki | 349 | 646 | 2399 | 〜4700 | 11 | 7798 |
| chugoku | 347 | 625 | 2357 | 〜3900 | 17 | 6871 |
| shikoku | 207 | 390 | 1417 | 〜2300 | 9 | 4090（実測: 約 3,000 件・約 360MB・約 10 分） |
| kyushu | 507 | 1025 | 3541 | 〜6000 | 29 | 10563 |

- 取得は **1 秒あたり 5 件まで**（`tools/real/lib/fetch.ts` の `RATE`。上げない）。User-Agent は汎用の名前で、個人情報は入れない
- L03-b（土地利用）は 1 次メッシュごとの zip が約 20MB。地方あたり 10〜30 個。`tmp/realdata/l03b/<メッシュ>.u8` に展開済みの格子を残すので 2 回目は速い
- **キャッシュはコミットしない**（`tmp/` は .gitignore）。別のセッションでは取り直しになる

## 3. 出力（区域ファイル）

`public/data/areas/<地方>/<セル>.bin`（gzip）と `index.json`。中身（`src/gen/real/format.ts`）:

| 部分 | 内容 | 細かさ（実在 / 区域） |
|---|---|---|
| 標高 | 129×129 点、0.5m 刻み、海は「海」の印 | 78m / 8m |
| 土地利用 | 129×129 点（標高と同じ点）: 田・畑・森林・荒地・建物用地・道路・鉄道・その他・水面・海浜・海・ゴルフ場 | 78m / 8m |
| 堅ろう建物の割合 | 64×64（国土地理院 z13 の堅ろう建物の面） | 156m / 16m |
| 人口 | 10×10（国勢調査 1km メッシュ、人/km²） | 1km / 102m |
| 線 | 高速・国道・県道・幅 13m 以上（人の少ないセルは 5.5m 以上も）・鉄道。トンネル・高架の印、実寸の幅 | 簡略化 1.2m |
| 点 | 駅・県庁・市役所・役場・病院・学校・大学・警察・消防・自衛隊・空港・城・寺社・郵便局…（名前つき） | 0.5m |

- 大きさの目安: **1 区域 平均 40KB 以下、全国 120MB 以下**。四国の実測: 平均 16.0KB・最大 20.3KB・合計 3.40MB（PROGRESS.md）。超えそうなら `durableMul`（6 節）や `REAL_AREA.build.simplify` を上げる
- `index.json`: セルごとの大きさ、**警察署・消防署の数、自衛隊の施設**（国土地理院の注記から数えたもの）。ゲームは起動時に全地方の index.json を読み、戦略地図のセル情報（`StaticCell.real`）をこの値で上書きする

## 4. 確認のしかた

### 自動点検（必ず全セル）

```
node tools/real/check.ts <地方>            # 全セル（1 セル 1〜3 秒。本拠としての生成・視線・隣との境界を含む）
node tools/real/check.ts <地方> --quick    # 視線と本拠を省く（速い）
node tools/real/check.ts <地方> --cells 21757,21758
```

点検の中身としきい値（`REAL_CHECK`、`src/data/realmap.ts`）:

| 項目 | しきい値 | 外れたときの直し方 |
|---|---|---|
| 乾いた土地のうち歩ける割合 | 60% 以上 | `heightMul` を下げる（6 節） |
| 高所の射点 | 3 か所以上（海が 6 割を超える区域は除く） | 足りなければ生成が鉄塔を足す。それでも足りないなら `addPois` に塔（POI 20）|
| 本拠の中央 半径 120m | 建物なし | 生成側で取り除く（失敗したら共通部分の不具合） |
| 東・南の隣との境界の高さの差 | 0.01m 未満 | 共通部分の不具合（標本化がずれている） |
| 境界の水面の不一致・相手のない道路の端 | 0 | 同上 |
| 建物が道路・水面の上 | 0 | 同上（R0 で施設と町の道の重なりを直した） |
| 区域ファイル | 80KB 以下 | 6 節の間引き |
| 生成時間（Node） | 900ms 以下 | ゲームでは Worker で作るので画面は止まらないが、重すぎると隣の区域の表示が遅れる |

視線の割合（地上で 200m 先が見える割合）は表の最後に区分ごとの平均が出る。目安は田舎 25〜45%、森 15% 未満（07b）。実データで外れても直ちに不具合ではないが、田舎が開けすぎなら生け垣・藪の量（`TACTICAL.cover`）は共通なので触らず、PROGRESS.md に値を書く。

### 見た目（スクリーンショット）

1. `node tools/real/area-preview.ts <地方> <セル>` → `tmp/realarea/<地方>_<セル>.png`（データそのもの。赤=国道、橙=県道、緑=高速、黒=鉄道、黄=駅、紫=自衛隊、水色=その他の施設）
2. `node tools/real/area-map.ts <セル>` → `tmp/realmap/<セル>.png`（ゲームが作る区域。青=水面、砂色=海浜）
3. 同じ 10km 四方を **地理院地図**（https://maps.gsi.go.jp/ ）で開いて見比べる。セルの範囲は `grid.json` の `proj` から: 経度 `lon0 + gx×10/kmPerLon`〜、緯度 `latTop − gy×10/kmPerLat`〜（`tools/real/cities-check.ts` が主要地点のセル番号を出す）
4. ゲームの中: `npm run build && npx vite preview`、`?seed=12` で新規ゲーム → 開発者ツールで `__game.debug.gotoLatLon(緯度, 経度)` → `__game.debug.realInfo()` で `real: true` を確かめ、高い所から見る。e2e の `e2e/realmap.spec.ts` が同じことを自動で行い `test-results/realmap-*.png` を撮る（地点の表を自分の地方に書き換えて使う）

見比べる点: 海岸線、川（大きな川は水面として出る）、主要道路の向き、鉄道、町の広がり（建物用地）、山の形（標高の陰影）、駅・役所・病院の位置。

## 5. よくある不具合と直し方

| 症状 | 原因 | 直し方 |
|---|---|---|
| 急斜面で歩けない（walkable が低い） | 高さの縮め方が足りない | そのセルの `heightMul: 0.8` など（6 節）。地方全体なら `OVERRIDES.heightMul` |
| 区域のほとんどが海や湖 | 海岸のセル（戦略地図では陸の割合 35% 以上で陸） | 不具合ではない。本拠にはなりにくい（中央 140m は陸に直す処理あり） |
| 建物が道路や川に重なる | 生成の順番（道路 → 施設 → 町の道 → 町並み → 田畑） | 共通部分。PROGRESS.md に「共通部分を直した」と書いて最小限の修正 |
| トンネルの出口で道が山に突っ込む | トンネル区間は描かない（`LINE_TUNNEL`） | そのまま（坑口で道が終わる）。気になる区間は 6 節で点を足して目印に |
| 高架・橋 | R0 は橋桁を作らず、水面の上は道路の下を **土手（盛り土）** にする（L9: 名所の橋は表の線に沿って本物の形の橋に置き換わる。L10: 幅 30m 以上の水を渡る道路の橋と鉄道は桁橋。7 節の L9・L10） | 30m 未満の小川・水路と、橋の印の無い道路は土手のまま。区域のデータを作り直したら `node tools/real/bridges.ts` |
| 境界で川や道路がずれる | ほぼ起きない（両側で同じ点を標本化） | 起きたら `check.ts` の seam 列で分かる。データの作り直し（`--cells` で両方）で直らなければ共通部分の不具合 |
| 隣の地方との境界で地形が段になる | 隣の地方のデータがまだ無い（乱数の区域） | 隣が無いセルの辺は 120m の帯で乱数の地形へ混ぜる（`REAL_AREA.seamBand`）。隣の地方が揃えば自然に消える |
| 施設の名前が違う・重複・位置がずれる | 注記の位置は文字の位置（施設の中心とは限らない） | `dropPois` / `renamePois` / `addPois`（6 節） |
| 駅が無い小さな町 | z14 の注記は「町のタイル」だけ読む（建物用地が少ないタイルは読まない） | `REAL_AREA.build.labelTileTown` は共通なので、個別に `addPois` |
| 町が密すぎて重い | 建物用地が広い大都市 | 3 指標を計測して超えたら `durableMul` を下げる（高層が減る）。07d-1 の段階的な出現が効くので、まずは計測 |

## 6. 手直しの口（`tools/data/real/overrides/<地方>.ts`）

**自分の地方のファイルだけを触る**。型は `tools/data/real/overrides/types.ts`。直したら `npm run data:region -- <地方> --cells …` で作り直す（データに焼き込まれる。高さの倍率はファイルの頭に入り、ゲームが読む）。

```ts
import { POI } from '../../../../src/gen/real/format.ts';
import type { RegionOverrides } from './types.ts';

export const OVERRIDES: RegionOverrides = {
  heightMul: 1,                          // 地方全体の高さの倍率（1 = src/data/realmap.ts のまま）
  cells: {
    21757: {
      heightMul: 0.85,                   // このセルだけ平らに
      dropPois: ['簡易郵便局'],           // 名前に含む点を消す
      renamePois: { 松山市役所: '松山市役所（本館）' },
      addPois: [{ kind: POI.tower, grade: 0, x: 300, z: 420, name: '給水塔' }], // 区域の座標（m）
      durableMul: 0.7,                   // 高層を減らす（重いとき）
      dropLocalRoads: true,              // 5.5m 以上の細い道を入れない（人の少ないセルでだけ入る）
    },
  },
};
```

数値そのもの（高さの縮め方・町の格のしきい値・施設の大きさ）は `src/data/realmap.ts` にあり **全国共通**。変えたいときは取りまとめ役に相談（PROGRESS.md に理由を書く）。

## 7. 名所（L1〜L8。仕組みは L1 が作った）

各地の主要な観光名所を **外観だけ** の建物として、実在の位置を縮めた所に建てる。**作業は 3 か所（＋名前）だけ**で、区域の生成・描画・戦略地図のコードは触らない。

| やること | ファイル |
|---|---|
| 形（設計図）を書く | `src/gen/buildings/defs/landmark/<地方>/<名前>.ts`（`landmarkDef`、下の例） |
| カタログに登録 | `src/gen/buildings/catalog/landmark_<地方>.ts` の配列に 1 行 |
| 置き場所の表に 1 行 | `src/data/landmarks/<地方>.ts`（id・緯度経度・向き・任意で `poi` / `reach`） |
| 名前 | `src/ui/i18n/ja.ts` の末尾（L の節）に `'landmark.<名前>': '正式名称'`（キーは設計図の id） |

```ts
// src/data/landmarks/kanto.ts
export const LANDMARKS_KANTO: readonly LandmarkSpot[] = [
  { id: 'landmark.tokyo_tower', lat: 35.6586, lon: 139.7454, rot: 0 },          // rot: 正面（設計図の z = d 側）の向き 0 南 1 東 2 北 3 西
  { id: 'landmark.tokyo_station', lat: 35.6812, lon: 139.7671, rot: 1, reach: 80 },
];
```

### 仕組み（何が自動で起きるか）
- **置き場所**: `src/gen/real/landmarks.ts` が緯度経度 → セル → 区域の点（1/10 に縮めた位置）にする（格子は `LANDMARK_GRID`、grid.json と同じ）。区域の生成（`layout.ts`）は **施設より先に** 名所を「敷地」（07d-3 の site）として計画する（`sites.ts` の `planLandmark`）: 点から `reach`（既定 48m、だめなら 2 倍・3 倍）以内で、**国道・高速・鉄道・川と海にかからず**、高低差の小さい所。県道・広い道・細い道（`CUTS.landmark`）は敷地の柵で止まり、町並み・施設・物見櫓は敷地を避ける。敷地は均される（高さの基準は区域の地形）。表の `poi` に区域データの点の名前（注記か手直しの `addPois`）を書くと、その点に建つ（その点に物見櫓は建たない）
- 区域データに名前の無い名所も緯度経度だけで置ける。表の順に置くので、**近くに並ぶもの（札幌の 3 つなど）は大事な方を先に**
- **外観だけ**（`BuildingDef.exteriorOnly`）: 部屋・探索ポイント・開いた扉なし（`landmarkDef` が付ける）。描画は霧の先（`RENDER.enterables.landmarkFar` 900m）まで外観で、遠景の箱にしない。三角形の予算で遠景に落とされない。屋内のゾンビも湧かない（`BALANCE` の `indoor.weights` で 0）
- **地面**（`L.ground`）: 堀・運河の水面（敷地の地面から掘る）、芝生、舗装、砂利。多角形は敷地の中（設計図の座標）。区域でも試験用の地図でも同じ関数（`applyLandmark`）が当てはめる
- **射点**（`L.vantage`）: 展望台・天守の上など。外から登る道として `L.ladder`（外のはしご。中を通る場合は床と屋根に穴を開けて筒で囲う。テレビ塔・五稜郭タワーが例）
- **戦略地図**: 表から自動で、名所のあるセルに金色の菱形と名称（拡大時）、凡例「名所」、セル情報に「名所: …」
- **試験用の地図** `?landmarks=1`（`debug.openYard(4)`）: 全名所が平らな地面に並ぶ（水面・射点つき）。e2e `e2e/landmarks.spec.ts` が 1 つずつ地上 200m と上空から撮り、3 指標を測り、はしごを登る。`LANDMARKS=tokyo_tower,…` で自分のものだけ。実際の区域の地点は同じ spec の `CELLS` に足す

### 設計図の書き方（`src/gen/buildings/defs/landmark/common.ts`）
```ts
export const LANDMARK_X = landmarkDef({ variant: 'x', size: { w: [40, 40], d: [30, 30] }, eaves: 12, top: 30, build(L) {
  L.box(0, 0, 0, L.w, 12, L.d, 'paint', { paint: 'white' });                 // 箱。paint は data/render.ts の PAINT の名前
  L.shape('gable', -0.5, 12, -0.5, L.w + 0.5, 18, L.d + 0.5, 'paint', { paint: 'roofRed', axis: 'z' });
  L.column(20, 15, 3, 12, 30, 'paint', { paint: 'copper', taper: 0.3 });     // 12 角柱（taper 0 で円錐、>1 で上が広がる）
  L.bar(ax, az, bx, bz, y0, y1, 1.2, 'paint', { paint: 'stone' });           // 2 点を結ぶ斜めの壁・梁（yaw）
  L.ring(cx, cz, r, y0, y1, 0.2, 16, ...);                                     // 多角形の筒（手すり・円筒の壁）
  L.windows('x', L.d, 1, 2, L.w - 2, 10, 3, 5.5, 1.4, { broken: 0.4 });       // 面に窓（割れた窓は黒）
  L.ladder(x, z, nx, nz, 0, 30); L.vantage(x, 30, z);                          // 登る道と射点
  L.ground('water', [[0, 0], [10, 0], [10, 5]], 2.4, 0.9);                     // 堀
  L.car(…); L.tent(…); L.sandbags(…); L.crates(…); L.fallenSign(…); L.scorch(…) // 崩壊後 90 日（1〜2 点）
} });
```
- 部品の約束は 07d（`docs/buildings_guide.md`）のまま。すべて外観（`shell`）。当たり判定は部品から自動（`solid: false` は飾り、木の葉・細い手すり・模様に）。**新しく足した形**: `Part.yaw`（垂直軸まわりの回転。当たり判定は長い辺に沿った小さな箱の列）と `cyl`（12 角柱、`taper`。当たり判定は内接する四角）
- 色: 材質 `paint` の名前つきの色（`PAINT`: 白・黒・朱・インターナショナルオレンジ・赤レンガ・銅緑・金・石…）。足すときは `PAINT` の **末尾に追記**（順番で色が決まる）
- 三角形: 外観 6,000 まで（`ARCH.limits.landmark`）。大きな塔・城は `landmarkDef({ shell: 8000 })` と PROGRESS.md に理由。箱 12・屋根 8・`cyl` 44
- カタログの自動検査は名所には外観の検査だけ（決定性・三角形・生成時間・敷地に収まる・当たり判定の箱が描いた部品と重なる・地面と射点が敷地の中）。`tests/landmarks.test.ts` が表（設計図・名前・全名所が表にある）、試験用の地図（はしごを登って射点に着く）、実際の区域（データのある地方の全名所が建ち、敷地に他の建物が無い）を検査する
- **扱いの注意**（発注者の決め事）: テーマパークは名前・ロゴ・キャラクター・特定のアトラクションを使わない一般的な形に。慰霊・追悼の施設と政治的な議論のある施設は作らない。原爆ドームは作るが、崩壊後の演出・射点・登れる足場を付けず、周り 60m にゾンビを初期配置しない（L6。必要な仕組みは L6 が足す）

### こつ（形・三角形の節約）
- 遠目の輪郭と色が勝負。細部（窓 1 枚ずつの枠）より、比率・屋根の色・塔の形。窓は壁を切らずに薄い板を貼る（`L.windows`、1 枚 12 三角形）
- 大きな敷地（城郭・公園）は主役＋数点。五稜郭は実寸だと区域の半分になるので星形を約 1/4 で描き、堀と石垣と奉行所だけにした（設計図の頭に理由を書く）
- 格子の塔（テレビ塔）は脚を高さ方向に段の箱で寄せ、水平の輪を数段。斜材は yaw で平面上の斜めしか作れないので、面の中央に縦材を足すと格子に見える
- 円・円錐は `L.column`（`cyl`）1 部品。星形・菱形は四角を yaw で 45° 回す
- 木の葉（樹冠）は `solid: false`。幹だけ当たる
- 区域で置けなかった名所はテストが落とす。`reach` を広げるか、`rot` を変える（細長い敷地は道路の向きに合わせると入りやすい）

#### L2（東北）からの追記
- **置けない理由を先に調べる**: `planLandmark` が断るのは ① 区域の端（敷地は端から 14m 以上内側。セルの境にある名所は境から半分の奥行きだけ動く）② 国道・高速・鉄道・水面 ③ 高低差（100m 未満の敷地は 6m、以上は 14m）。高低差は区域の高さ（`map.height`）を敷地の大きさで走査すると分かり、線は `map.roads` を点の周りで並べると分かる。`reach` を広げても遠くへ逃げるだけのことが多い
- **表の `level`（m）**: 山腹の寺社（山寺）は縮めた区域では高低差 20〜30m の斜面に立つ。`level: 30` で敷地を段に均して建てる（背面を山側に向けると切土が名所の裏に隠れる）。平らな高台の上の名所（仙台城跡）も、区域では急な丘になるので `level: 12` で本来の位置に来た
- **表の `drain`（0〜1）**: 城は区域データに **本物の堀の切れ端**（水面）が残っていて、それが敷地を断る（弘前城・鶴ヶ城）。`drain: 0.2〜0.25` で敷地のその割合までの水面を埋めて建てる（設計図が自分の堀を掘る）。海・川も埋まるので小さく
- **敷地を小さくするのが一番効く**ことがある: 鶴ヶ城は 80×72m では国道 2 本とセルの端に挟まって 107m 先へ逃げたが、64×64m で 42m に収まった。足元の広がりは主役の周りだけにする
- **城の天守**: `defs/landmark/tohoku/parts.ts` の `tier`（白壁・格子窓・寄棟の裳階）を下から積み、次の層は軒の高さから立てる（屋根の斜面の中に壁の根元が隠れる）。最上層は `topRoof`（寄棟＋切妻の入母屋・鯱）、`chidori` で斜面の千鳥破風、`stoneBase` で反りのある石垣（上ほど内へ寄る箱 4〜5 段）。5 層で 3,300 三角形。高さの大半は石垣と屋根なので、層の高さは 3.5〜4.6m、屋根の出 1.3〜1.6m
- **枝垂れ桜**: 円錐を重ねるとピンクの杉に、円柱の幕にすると樽に見える。丸い傘（`cyl` taper 0.45）の縁から細い板（`bar`）を 9 枚、長さを変えて垂らすと隙間から幹が見えて枝垂れて見える（`weepingCherry`）
- **岩山**: 箱を積むとビルに見える。`L.shape('cyl', …)` の楕円柱を先細り（taper 0.5）で重ね、肩と頂に濃い緑の樹冠を載せる（頂が平らだとサイロに見える）。登る面（はしご）だけ箱の平らな面にする
- **斜張橋のケーブル**: 部品は垂直軸しか回せないので、斜めの線は細い箱 26 個の階段（`slant`、1 本 312 三角形）。8 本で 2,500 三角形。遠目には線に見える。主塔の脚の傾きも 16 段の箱
- 色は `PAINT` の末尾に `sakura`（桜）・`bronze`（銅像）・`cedar`（杉の濃い緑）・`thatch`（茅葺）を足した。木の色は `PAINT` ではなく材質 `'woodDark'` / `'wood'`

#### L5（近畿）からの追記
- **大きな駅・施設の敷地を食わない**: 名所は施設より先に置かれるので、駅の大きな敷地（政令市の駅は 240〜280×150〜180m）の中に名所の点があると、駅が一回り小さい型に落ちる（京都駅が政令市の駅 → 県庁所在地の駅、天王寺駅が県の駅 → 市の駅になった）。**名所を足したセルは、駅・空港・基地の型が変わっていないかを確かめる**（`map.placements` の `transport.*` を名所の無い表と比べる。全国の集計の `types` の差でも分かる）。直し方は、名所の点を駅の敷地の外へずらす（東寺は 1.6km 南西）か、`reach: 16` で点に留める（通天閣: 既定の 48m だと国道を切る長さの少ない駅の側へ寄った）
- **敷地がすべて海**（明石海峡大橋の主塔）は `drain: 1` でも置けない: `planLandmark` の水面の数え方は敷地の端のタイルを含むので、全面が水だと割合が 1 をわずかに超える。`drain: 1.1` にする。さらに置き場所の点数は「切る道路の長さ」を足すので、橋（高速）の上に建てたい名所は遠くの陸（切る長さの短い所）へ逃げる。`reach: 16` で点に留める
- **斜めの橋**: 区域の橋が 45° に走るときは、設計図の中で橋を対角線に沿わせる（`kinki/akashi_kaikyo_bridge.ts`: 橋の向きの単位ベクトルで点を作り、桁・弦材は `beam`、斜材とケーブルは `slant`、脚は `yaw: π/4` の箱）。敷地は正方形にして対角線に桁を通す
- **城の点はたいてい堀の上**（大阪城・姫路城・彦根城・和歌山城）: `drain: 0.3〜0.4`。大阪城は上町台地の段差で `level: 14`、周りの阪神高速で `cutRoads`
- **同じセルの名所の順**: 大きな敷地の名所が小さな名所の場所を先に取ることがある（大阪の通天閣とハルカス、奈良の東大寺と興福寺）。`landmark-why.ts` の地図の `o` が自分の敷地のこともある（自分を無視できていない）ので、`o` に囲まれたら表の順を入れ替えて試す
- **`landmark-why.ts` の名前は部分一致**: `toji` は `kenrokuen_kotoji` や `nachi_seigantoji` にも当たる。`landmark.toji_pagoda` のように全部書く
- **置けない理由を正確に知る**: `landmark-why.ts` は近似なので、`sites.ts` の `planLandmark` の候補ループに一時的に `siteDebug.log` で `whyNot` と `rangeOf` を出す行を足して `mapFor` を呼ぶと、候補ごとの理由（`edge` / `taken` / `water` / `line<種類>`、高低差）がそのまま分かる（コミットしない）
- **五重塔・三重塔**（`kinki/parts.ts` の `pagoda`）: 遠目は屋根が主役。壁の高さは階の間隔の半分以下にし、軒下に暗い組物の帯を 2 段（出の小さい帯と大きな帯）、屋根の縁を厚く。壁を白くすると「白い塔に薄い板」に見えるので、東寺・興福寺は壁を `hinoki`（くすんだ茶）にした。朱塗り（清水寺・青岸渡寺）は柱も壁も朱
- **千本鳥居**: 鳥居 1 基を箱 4 つ（柱 2・貫・笠木、48 三角形、`boxTorii`）にして 36 基 × 2 列。丸い柱の鳥居（`chubu/parts.ts` の `torii`）だと 1 基 300 三角形を超える。上空からは森の中の朱の 2 本線、中からは朱のトンネルに見える
- **懸造（清水の舞台）**: 敷地は均されるので、斜面は設計図の中の「段の箱」（高さ 12m の台地、正面が崖）にし、舞台を崖から突き出して地面から柱を立てる。柱と貫は明るめの木の色（`hinoki`）にしないと暗い森に沈む
- **巨大な崖と滝**（那智の滝）: 1 枚の高い箱は「緑のビル」に見える。両脇を奥へ高くなる `wedge`（`slope: 'z-'`）の森にし、真ん中だけ暗い岩の面と白い水の帯にすると山の谷に見える
- **空いた穴**（梅田スカイビルの空中庭園の円）: 垂直な面の円の穴は、水平な板を段ごとに穴の左右に分けて積み、穴の縁に白い輪（`xyLine` の 20 辺）を付けると遠目に分かる。板の下面は地面の照り返しで暗い緑に見えるので、輪が無いと穴に見えない
- **顔・時計の文字盤**（太陽の塔・京大の時計台）: 垂直な面の円は `kinki/parts.ts` の `disc`（水平な板を円の幅で 6〜8 段）
- 試験用の地図の名所の間隔を 24m → 16m にした（78 種類で列が地図の南端を越えた）。**L6〜L8 で足りなくなる**（1024m の地図に 78 種類で敷地の面積の 4 割、間隔 16m で最後の列は z ≈ 886）。地方ごとに分ける（`?landmarks=<地方>`）などの手当てが要る
- 三角形: 近畿の 21 種類はすべて 6,000 以下（最大は伏見稲荷の 5,852。千本鳥居 72 基で 3,456）。神戸ポートタワーの双曲面は直線の部材 24 本 × 5 区間 × 2 段で 5,320（区間 6 × 3 段だと 7,600）

#### L9（橋の名所を端から端まで）
- **橋の名所は敷地でなく「線」**: 表の行に `bridge: { path: [[緯度, 経度], …], ends: [始点の高さ, 終点の高さ], water? }`（`src/data/landmarks/types.ts`）。`path` は岸から岸までの桁の中心線（最初と最後の点は乾いた陸、区域の道路が来る所）、`ends` はそこの地面の高さ（ゲームの m。区域の高さを `tools` で測って書く）、`water` は川の水面（既定 0＝海）。`rot`・`reach`・`level`・`drain`・`cutRoads` は使わない。`lat` / `lon` は橋の真ん中（戦略地図の印）
- **設計図は `defs/landmark/bridge.ts` の `bridgeDef(設計)` だけ**: 径間（実物の m の列。主塔・アーチの数はここから決まる）、主構造の種類（`suspension` 吊り橋・`stayed` 斜張橋・`arch` アーチ・`girder` 桁橋）、桁（幅・2 層 `upper`・トラス `truss`・線路 `rails`）、主塔（`portal` 門形・`pole` 一本柱（逆 Y）・`aFrame`）、ケーブル（`cable`：垂れ・ハンガー間隔・アンカレイジ）、斜材（`stays`：本数・一面 / 二面）、橋脚（`piers`）、桁の高さ（`profile`：水面からの高さ・勾配の上限・中央のむくり・アーチの高さ）。部品は 1 つの関数がすべての橋で同じに作る。個々の橋のファイルは設計の値だけ（`kanto/rainbow_bridge.ts` が例）
- **区域では**（`src/gen/real/bridges.ts`）: 線が通る区域ごとに ① 線に沿って走る道路・鉄道（幅＋3m 以内、向き ±45°）を切る（桁が運ぶ）② 水の上は地面を桁の高さまで上げ（水面は残す）、その地形のタイルは描かない（`TacticalMap.decks`）③ 陸の上は地面を変えず、橋の見えない箱（2m 格子、急なアーチは 0.5m）が桁を支える（道路と人が高架の下を通れる。L10 から水の上も箱で支え、地面を上げない）④ 端の先 3m は桁の端の高さ、さらに 14m かけて元の地面へ ⑤ 端に道路が来ていなければ、端の外側の最寄りの道路へ 8m の道を引く ⑥ 桁の上のタイルは傾きに関係なく歩ける（`deckWalk`：ゾンビが渡る）⑦ 施設・町並み・木は桁の下と端の周りに置かない。配置（`placement.span`）は回さない（rot 0）。当たり判定は線の 16m ごとの包み箱
- **2 つの区域にまたがる橋**（明石海峡大橋: 20274 と 20441）: 両方の区域が同じ線・同じ `ends` から同じ高さを計算し、自分の区域の中の区間（`from`〜`to`、区域の辺で正確に切る）だけを作る。共通の辺の地面は一致する（`tests/bridges.test.ts`）。端の高さを片方の区域の地面から取ると一致しないので、`ends` は表に書く
- **線の取り方**: 区域データの道路（`flags & LINE_BRIDGE`）の点を緯度経度に戻す（`node` で `realInCell` の逆算。L9 は作業用の道具で区域の線と土地利用を並べた）。区域データに道路の無い橋（青森ベイブリッジは市道で幅の区分が細いので区域に無い）は国土地理院のベクトルタイル z16 の `road`（`ftCode` 2703・`lvOrder` 1）から取った。主構造の位置は `at`（線の始点からの m）で、主径間が区域の水の真ん中に来るように
- **高さの決め方**: 平面は 1/10 だが桁の幅と人は実寸なので、桁は「両端から 7.5% の坂で届く高さ」までしか上げられない（桁下 6〜16m）。主塔は **主塔の高さ ÷ 桁の高さ** を実物に合わせる（レインボーブリッジ 2.1・明石 4・青森 2.4・関門 2.3・大鳴門 3.4）。主塔 ÷ 径間で合わせると塔が桁の 2 層に埋もれる
- **歩けるかを先に試す**: 桁の上の柱（逆 Y の一本柱は車線の真ん中に立つ）・アンカレイジの門（頭上 5m 以上）・欄干（曲がり角で内側は短く、外側は延ばす）でつかえやすい。`tests/bridges.test.ts` が区域ごとに両方向に歩く（車線は `LANES`）。e2e は `e2e/bridges.spec.ts`（`BRIDGES=rainbow,…`）
- 三角形: 長い吊り橋はケーブルを高さ 1.4〜2m ごとの箱の階段、ハンガーは 5〜15m ごと、トラスは格子の斜材 1 方向・柱なしで 8,000 以内（明石 6,400・レインボー 7,000）。試験用の地図では橋全体が 1 つの敷地に入る（明石 490m）

#### L10（普通の橋と、残りの長い橋）
- **普通の橋**: 区域の道路の橋の区間（`LINE_BRIDGE`）と鉄道（鉄道は橋の印が z13 に無いことが多いので全部）のうち、**水を 30m 以上渡り、その真ん中を通る水の最も短い弦（12 方向）も 30m 以上** の所を桁橋にする（`REAL_BRIDGES`）。表 `src/data/bridges/ordinary.ts`（1,478 行）は **`node tools/real/bridges.ts` が区域ファイルから作る**（ネットワーク不要、約 1 分。`--count` は数えるだけ）。**区域のデータを作り直したら必ず回す**（`tests/bridges.test.ts` が表を検査する）。行: `k` 道路 0・鉄道 1、`w` 桁の幅、`c` 線に沿う道路を切る帯の半幅、`e` 両端の高さ、`l` 水面、`r` 線路、`p` 線（戦略地図の格子の北西の角からの縮めた m。セル = floor(z/1024)×167 + floor(x/1024)）
- 表の作り方: 区域の辺をまたいで線をつなぎ、水の連なり（16m 以下の中州はつなぐ）を岸から岸まで取り、両岸へ「水面 +3m に 10% の坂で届く」所まで延ばす（最大 40m、乾いた地面で止める）。幅の広い順に残し、**並んで走る線（両方の桁の半幅 +1m より近い）は広い方の桁にまとめる**（帯を広げて切り、鉄道なら線路を桁に描く）。名所の橋の線から 40m 以内は作らない（名所の表を変えたら表を作り直す）
- **区域では**（`gen/real/bridges.ts`、設計 `defs/landmark/ordinary_bridge.ts` の 2 種類: 道路のコンクリート桁・鉄道の鋼桁）: 線に沿う道路・鉄道を `c` の帯で切り、**水の上は橋の見えない箱が桁を支える（地面も水面も変えない。桁の下 2m を人が歩いて渡り、弾と視線が通る）**、陸の上の坂は地面を桁の高さまで上げる（土の盛り土。町の道はその上を越える）。橋脚は水の中だけ 7m ごと。描画は名所と同じ形ごとのプール（ドローコールは増えない）
- **辺の近くの橋**: 線が区域の外 40m 以内を通る橋も両方の区域が取る（`from` > `to`：配置はせず地面だけ）。端の先の盛り土・帯が辺の上の高さを変えても両側で同じになる（364 組の辺で差 0 を確かめた）
- **名所の橋も水の上は箱で支える**（L10 で `carry` の既定を `boxes` に。L9 の「地面を上げる」は `carry: 'ground'` で残してある）。端が水の上にある名所の橋（来島海峡大橋の 3 行の継ぎ目）は、端の先の地面をならさず、道路もつながない
- **長い連続橋**: 1 橋 1 行（瀬戸大橋 6 行・来島海峡大橋 3 行・多々羅大橋・因島大橋）。続く橋は前の橋の最後の点と同じ点・同じ高さから始める。区域の無い海のセルの行（瀬戸大橋の中の 5 橋、20764）は戦略地図と試験用の地図にだけ出る。`at` は試験用の地図でも効くので、`yard.length` は `at` ＋ 主構造が入る長さにする
- 斜張橋の斜材が多いと三角形が増える（主塔が高いほど箱の段が増える）。`stays.step`（段の高さ、既定 0.9m）を大きくする
